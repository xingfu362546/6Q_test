## 3. 技术可行性

| 项 | 结论 | 说明 |
| --- | --- | --- |
| 版式分支 | 可行 | 同一路由内按 `resultLayout` 分流，URL 与返回栈不变 |
| 五维雷达 | 可行 | 现有 `radarSvg` 已按维度数组渲染，只需补分数标签与配色 |
| 底部分层固定 | 可行 | `position: fixed` + `translateX(-50%)`，与现网底部栏同套路 |
| 呼吸动画 | 可行 | 纯 CSS keyframes，无定时器；`prefers-reduced-motion` 可关 |
| 二维码抽屉 | 可行 | 复用现有弹层模式，不新增依赖 |
| 海报 9:16 | 可行 | Canvas 直接绘制 810×1440；现网走 html2canvas 截 DOM，两条路径都已验证 |
| 档位一致性 | 可行 | 档位与区间同源，百分比随档位下发 |

## 4. 现网实现要点（读源码得到）

1. `viewCheckResult` 返回 `templete` + `scoreList` + `weiduExplainList` + `explain` + `historyItemList`，前端据此拼装，**服务端不返回渲染好的文案**，所以档位文案只能来自 `templete.results`。
2. `scoreList[i].value = score / maxScore * 100`，即前端拿到的是百分比。新版式要显示「(11分)」，必须同时用 `maxScore` 还原，或让后端直接给 `score`。本版按「用 maxScore 还原」实现，避免改既有字段语义。
3. 现网海报是 `html2canvas` 截 DOM + 模板 `reportImg` 做底图，因此换风格必须同时换底图与结构，单纯改配色不够。
4. `getZtfbScore` 只服务正态分布图，新版式不需要。
5. 现网 `ResultPoster` 里有 `base.slice(0, 94)` 的截断逻辑，新版式金句较短，不再截断。

## 5. 基线遗留缺陷

`harmonyDims` 原实现写死 `["AQ","EQ","CQ","IQ","RQ","SQ"]`，
五维商品进入「我的测评」时会出现六个维度、其中五个「未点亮」。
本版一并修：按记录携带的维度动态生成，标题也随维度数变化。
