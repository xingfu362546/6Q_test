# 分享海报 → 扫码进入：链路规格（v2.1.0）

> 对应需求：EX-206（海报）、EX-207（雷达取数）、EX-208（分流与免费建单）、EX-209（推荐关系）、EX-210（登录校验）
> 落地页：`6Q_exam_h5/entry.html`（原型新增）

## 1. 为什么需要这一层

v2.0.0 里测评必须先有订单，用户从订单点「测试」才进测评。
海报二维码只指到详情页，于是免费测评也要走「详情 → 确认订单 → 0 元支付 → 订单 → 测试」四步，
每一步都是流失点；同时 H5 没有保存推荐关系，扫码下单的业绩归不到分享人。

v2.1.0 用统一落地页把这段收敛成一步，并在进入链路里补齐登录与推荐关系。

## 2. 总流程

```
                 ┌──────────────────────────┐
海报二维码（带 ref）│  entry.html?goodsId&ref  │
                 └────────────┬─────────────┘
                              │ ① 先落推荐关系（未登录也写）
                              ▼
                    ┌─────────────────────┐
                    │ ② 是否已登录？       │
                    └──────┬───────┬──────┘
                      否   │       │  是
                           ▼       ▼
                  登录页(redirect)   ③ 商品价格判定
                           │            │
                    登录成功回跳          ├── price = 0 ──► ④ 自动建免费订单
                           └────────────┘        │
                                                 ▼
                                        ⑤ 进入测评须知（无感）
                                                 │
                                      price > 0 ─┴──► 商品详情页（用户自行下单）
```

## 3. 分流规则

| 条件 | 动作 | 用户感知 |
| --- | --- | --- |
| 商品 `price = 0` | 自动创建免费订单（金额 0、状态已完成），再进测评须知 | 无支付页、无确认页，最多看到一句「已为你开通免费测评」 |
| 商品 `price > 0` | 跳商品详情页，不代下单 | 正常浏览与购买 |
| 同一商品已有免费订单 | 复用该订单，不新建 | 「已为你打开测评」 |
| 商品价格为空或非数字 | 按收费处理（安全侧） | 进商品详情 |

免费订单字段：`price = 0`、`payAmount = 0`、`status = finished`、`channel = scan_free`、`referrer`。

## 4. 推荐关系

| 环节 | 规则 |
| --- | --- |
| 二维码 | 地址带 `ref`（分发人标识）与 `goodsId`；真实环境由 `createShare` 生成同结构链接 |
| 落地页 | 进入后**第一时间**写 `exam_referral`，早于登录判断 |
| 冲突 | 已有推荐人时以**首次**为准，后一次分享不覆盖 |
| 订单 | 免费与收费订单都写 `referrer`，提交业务系统 |
| 展示 | 订单确认页显示推荐人，便于核对归属 |

## 5. 登录校验（重点）

| 项 | 规则 |
| --- | --- |
| 登录态判定 | 本地 `exam_session` 存在 `token` 即已登录 |
| 未登录 | 跳 `login.html?redirect=<落地页完整地址>` |
| 登录成功 | 按 `redirect` 回落地页**继续**，不是 `history.back()` |
| 参数保真 | 跳登录前已落库 `goodsId` 与推荐关系，回跳后从地址与本地恢复 |
| 环境 | **H5 与 APP 内嵌（含微信 / 凡泰环境）一律要求登录**，不因容器跳过 |
| 时序 | 登录成功后才允许建单与进测评；未登录不产生任何订单 |
| 已登录 | 直接进分支，不二次拦截 |

边界：
- 直接访问 `quiz.html` / `notice.html` 等内部页不做拦截（原型内已有入口默认已登录），拦截只发生在扫码落地页。
- 登录接口失败时停在登录页提示重试，不回跳，避免带着空 token 继续建单。

## 6. 海报雷达取数（EX-207）

```
dims      = record.dims                      // 五维，value 为百分比
maxPer    = round(record.total / 维数)        // 五力 = 12
raw[i]    = round(dims[i].value / 100 * maxPer)
点位       = raw[i] / maxPer
标签       = 维度名 + "(raw[i]分)"
```

无 `record`（详情页分享）时 `raw` 取各维 8 分示意值，不谎报成绩。
报告页与海报读同一份 `dims`，同一份答卷两处图形一致。

## 7. 接口

| 接口 | 用途 | 改动 |
| --- | --- | --- |
| `POST /security/api/user/share/center/createShare` | 生成带 `ref` 的分享链接 / 二维码 | 不改，`sourceParam` 带上 `goodsId` 与 `ref` |
| `POST /security/api/user/login` | 登录换 token | 不改 |
| `GET /security/api/user/info` | 取会员信息 | 不改 |
| `POST exam/order/create` | 建单（含免费单） | **新增** `referrer`、`referrerGoodsId`、`channel=scan_free` |
| `GET exam/exam/templete/detail` | 取商品价格与模板 | 不改 |
| `GET /exam/app/api/viewCheckResult` | 海报雷达与档位 | 不改（用既有 `scoreList`） |

## 8. 数据与本地存储

| key | 内容 |
| --- | --- |
| `exam_referral` | `{ ref, goodsId, from, channel, ts }`，首次优先 |
| `exam_orders` | 订单数组，含免费单与收费单，均带 `referrer` |
| `exam_session` | `{ token, userId, loginAt, channel }`，登录态判断依据 |

## 9. 验收清单

- [ ] 未登录扫码 → 跳登录，登录后回到落地页，参数不丢
- [ ] 免费商品扫码 → 自动建单（金额 0、带 referrer）→ 直接进测评须知
- [ ] 同一免费商品再次扫码 → 复用订单，不重复建
- [ ] 收费商品扫码 → 进商品详情页，不建单
- [ ] 订单确认页显示推荐人；收费订单携带 referrer
- [ ] 海报雷达每维带分数，标注规则与报告页一致
- [ ] 已登录用户扫码 → 不二次弹登录

## 10. 已知边界

- 原型用「模拟扫码进入」链接替代真实二维码跳转；真实环境由 `createShare` 生成带参链接。
- 免费订单只在前端 mock，不真正调后端下单；接入时按第 7 节补字段。
- 推荐关系以首次为准，是业务口径，若后续需要「末次归因」需另行确认。
